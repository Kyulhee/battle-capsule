# 마스터플랜

> 최종 업데이트: 2026-09-11. 남은 작업은 마일스톤 -> 트랙 -> 종료 조건 -> 다음 slice 순서로 관리한다.

## 현재 제품 목표

Battle Capsule은 low-poly quarter-view tactical roguelite battle royale이다. 현재 목표는 “많은 봇이 도는 시뮬레이션”을 넘어, 외부 사용자가 설명 없이 설치하고 10-15분 Night BR 한 판을 완주·재시작할 수 있는 Windows 무료 데모를 만드는 것이다.

첫 공개 지원 범위는 Windows x64, 오프라인 싱글플레이, 한국어, 키보드/마우스, `night_br_m1_60` 한 맵이다. macOS Universal 2는 프리릴리즈 호환성 피드백용 교차 빌드를 제공할 수 있지만 실제 Mac·서명·공증 gate 전에는 지원 플랫폼으로 승격하지 않는다. 99봇 기본값, 온라인, 영어·controller, 완전한 flashlight/fear/battery는 이 범위에 포함하지 않는다.

날짜는 1인 풀타임 개발 기준 계획 창이며 약속된 출시일이 아니다. gate 실패 시 날짜보다 원인 수정과 재검증을 우선한다. 이번 제안으로 출시 창을 앞당기지 않는다. 붕괴·폭격·특수 장비를 필수화할 경우 기존 창을 그대로 유지하지 말고 비용과 QA 범위를 먼저 재산정한다.

현재 개발 후보는 internal pre-alpha이며 공개 stable은 `v2.0.0-pre-expansion`을 유지한다. 새 package·수동·M2/M3 gate가 닫히기 전에는 공개판을 교체하지 않는다.

## 현재 기준선

- M1 개발 맵: `data/mapSpec_night_forest_expanded_candidate.json`
- M1 공통 preset: `night_br_m1_60` (일반 실행·수동 플레이·후보 페이싱 검증)
- 구조 부하 gate: `target_99_probe`; 제품 gameplay·출시 규모의 근거로 사용하지 않음
- 존 기준: 첫 축소 시작 120초, 완료/stage2 260초, stage3 540초.
- E-062 cover commitment는 자동 5-run을 통과했으나 수동 3판에서 초기 생존/이탈 압력이 거부됐다. E-063 전 표적 예측 사격은 봇 사망을 앞당겨 폐기했고 E-064 player-only로 좁혔다.
- 직전 E-064 자동 5-run은 평균 694.3초, alive@30/60/90/120/180/260 중앙 `53/38/32/27/22/17`, first upgrade 3.40초다. 수동 저장 1판은 372.5초·2위, alive@120/260 `18/4`이며 난이도/자동-수동 괴리는 미해결이다.
- E-065 소리 반응은 사용자 근접 체감 개선, 후방 급회전 잔여 관찰이다. 60봇 1-run 683.2초·alive@120/260 `24/12`는 sanity이지 새 5-run 승격 근거가 아니다. 실행 파일과 수동 기록은 CURRENT/PLAYTEST가 소유한다.
- `04bed12` clean Windows EXE 부팅과 Windows/macOS PCK inventory·메뉴 식별 PASS. 실제 Mac, 새 후보의 사람 전체 루프/성능/재시작·저장 검증을 대신하지 않는다.
- 과거 E-056/E-058/E-060/E-061 실패 후보는 재혼합하지 않는다. 당시 성능/99 구조/상태 진단 상세는 DEVLOG·EXPERIMENTS와 Git 이력을 참조하며 최신 후보의 통과로 재사용하지 않는다.

### 보급·점유·자기장의 역할

- 기존 `LootSpawner`의 지역 풀·POI 보장 슬롯·앵커와 드랍/wave TTL을 재사용한다. 총은 지역별로 고르지만 initial 소비품은 풀에서 별도 추첨하므로 **호환 탄약이 실제로 공급되는지** 먼저 확인한다. 단순 드랍 확률/전역 수량 증가는 첫 후보가 아니다.
- 기존 총·탄·장비 총량 예산을 고정한 채 주요 거점 여러 곳에 더 높은 품질과 쓸 수 있는 보급 묶음을 분산한다. 외곽은 낮은 티어와 최소 자립 보급으로 위험을 피할 대안을 남긴다. 특정 총에 맞는 탄을 보급 앵커 가까이에 두는 후보와 AI 변경은 분리한다.
- 총 없음/호환 탄 부족/단순 장비 업그레이드 욕구를 분리한다. POI별 재고·동시 바닥 아이템 상한·탄약 묶음량·빈 앵커 상태를 다루되 제자리 무한 리필은 하지 않는다. initial/supply를 일괄 소멸시키지 않고 기존 death/wave TTL을 보존한다. 보충이 필요하면 예고된 유한 보급으로 별도 실험한다.
- 봇은 기존 필요·위협·도착 시간·점유 효용을 기반으로 저탄약이면 보급, 무장 완료면 엄폐/선점, 고위험이면 외곽/우회를 택하게 한다. 방문/관측한 고갈 정보는 일정 시간 기억하되 먼 거점의 실제 재고나 숨은 적을 전지적으로 읽지 않는다. 인원 분산을 위한 강제 랜덤 이동도 넣지 않는다.
- 존은 장기 회전/매치 종료, 보급은 자발적 목적지, 엄폐는 경로/점유 가치, 국소 위험은 일시적 자리 변경을 담당한다. 존 압력 부재는 120초/260초 생존자, 현재/다음 원 안 체류, 경계까지 거리·이동 시간부터 확인한다. 존이 오기 전 전투가 끝나는지와 원 내부에 머무르기 쉬운지를 분리하기 전 일정/피해를 강화하지 않는다.
- 필수 관찰은 사용 가능한 탄이 없는 시간·첫 장총, 거점 도착 전후 탄/티어 변화·잔여 재고, 이동 이유·점유 집중, 생존 곡선과 바닥 아이템 최고 수다. 기존 자료 우선, 모자란 항목만 계측한다. 격리 상태별 AI 선택→60봇 1-run→유효할 때 5-run→clean EXE 수동 3판 순으로 검증한다.

### 티어 표시의 잠정 계약

- 종류별 아이템 색은 티어 색으로 통일한다. 잠정 대응은 **T1 회색 / T2 초록 / T3 파랑 / 금색은 후속 최상위 슬롯 예약**이다. 현재 3단계 성능 티어를 색 4개에 맞추려고 늘리지 않는다. 금색의 실제 장비/기존 보급 등급 대응은 구현 전 아이템 전수 목록에서 확정한다.
- 레일건은 보라색 **특수** 표시를 우선한다. 보라는 금색보다 높은 공격력 티어가 아니라 다른 기능/사용 규칙을 뜻하며 기존 레일건 수치는 유지한다. `weapon_tier`, `equipment_tier`, 2단계 `rarity`를 임의로 같은 숫자로 취급하지 않는다.
- 무기 종류는 실루엣·이름, 티어는 색+T번호/명칭, 특수는 별도 배지로 구분한다. 탄약은 호환 총종과 수량을 우선 표시하며 기존 색만 보고 고가치/glow를 판정하는 코드는 의미 데이터 기준으로 바꿀 대상으로 둔다. 소비품의 등급 대응은 실제 데이터에 있는 차이만 표시한다.
- E-066은 static `.tres`/사망 드랍을 공통 표시 resolver로 처리하고 focus 색·HUD 티어 배지를 연결했다. ammo는 중립색/호환 표시, 일반/고급 회복은 회색/초록이며 기존 동작 rarity는 바꾸지 않았다. 전투 진영·봇 성향의 식별색 제거까지 범위를 확대하지 않는다.

### 건물과 조건부 확장

- 비파괴 1차: 문 개폐·입장, 실내 파밍, 벽의 이동/시야/탄환 차단, 창 개구부의 양방향 제한 시야/사격, 창 외 별도 탈출 동선을 정의한다. 밖에서 실내 전체를 보지 못하지만 안에서도 무조건 밖을 볼 수는 없다. 지붕/앞벽의 카메라 가림 해소와 캐릭터의 실제 감지 규칙을 분리하며 단순 부쉬 판정 재사용으로 처리하지 않는다.
- 봇도 같은 문·창·청취/LOS 규칙으로 진입·수색·점유·탈출한다. 닫힌 문 경로, 문턱 stuck, 창 너머 벽 관통, 실내 pickup 불가, 문 앞 다수 봇 수렴을 격리 테스트한다. 기존 실외 거점과 비교해 안전한 파밍 선택과 공격 측 대응이 모두 존재해야 한다.
- 붕괴 2차: 누적 구조 피해→붕괴 예고/먼지→잔해의 상태 전이를 둔다. 공격량·무기별 구조 피해는 미정이며 영구 점유 해소 효과와 초반 붕괴 남발을 별도 비교한다. 먼지가 화면만 가리는지 실제 LOS도 가리는지, 잔해의 충돌/엄폐·nav 갱신·내부 actor/아이템 안전·프레임 비용을 확정해야 한다. 실시간 파편 물리보다 사전 제작 붕괴/잔해 상태부터 검토한다.
- 주기 폭격은 시스템이 만드는 이동 압력, 포격 요청은 사용자가 쓰는 특수 아이템으로 분리한다. 예고/안전한 탈출 시간·피할 경로·동시 영역 상한·쿨다운·존 중첩 방지부터 정의한다. 좋은 자리의 이점은 유지하고 영구 안전만 제한하며, 예고 없는 무작위 사망이나 반드시 같은 출구로 몰리는 설계는 폐기한다.
- 보라 아이디어 메모: **길리 슈트**는 걷기 중 감지 확정에 필요한 시간 +0.5초(달리기/발사·부쉬/유물 중첩은 미정); **섬광탄**은 몇 초간 수풀 포함 시야 공개(범위·대상·고체 벽 예외는 미정, 맵 전체 공개로 임의 확정하지 않음); **포격 요청**은 내 위치를 제외한 무작위 영역에 10초간 포격(제외 위치가 시전 시점/실시간인지, 안전 반경·경고·사용 횟수는 미정). 현재는 효과를 구현하지 않는다.

## 범위 확장 경계

- 신규 장소·무기·방어구 티어보다 현재 한 판의 가독성·피드백·첫 사용자 완주를 먼저 닫는다.
- 공개 데모 이후 반복성 부족이 실제 이탈 원인일 때만 두 번째 콘텐츠 축이나 보이는 진행을 추가한다.
- online/99 default/macOS 정식 지원/영어/controller는 각자의 비용·QA·운영 gate를 가진 별도 범위 결정으로 다룬다. 테스트 artifact 제공과 정식 지원 선언을 구분한다.

## 우선순위 원칙

1. E-065 근접 반응 개선은 유지하고 후방 반응은 잔여 관찰로 둔다. 기존 실패 후보 재혼합 없이 보상 가독성→거점 보급 흐름→실내 점유를 분리하며, 생존/보급 변경은 1→5-run·수동 gate를 다시 통과한다.
2. 점수·저장·export·버전·고지는 화면 폴리시와 별개의 release blocker이므로 M2 전에 N2-REL-01로 제거한다.
3. M2는 신규 콘텐츠가 아니라 플레이어가 실제로 보는 수관·캐릭터·전투·HUD·오디오·온보딩을 우선한다.
4. 공개 승격은 소스 실행이 아니라 clean packaged artifact와 외부 사용자의 무설명 완주를 기준으로 한다.
5. 큰 파일 리팩터링은 release slice가 닿는 경계에서만 작게 수행한다.
